In MongoDB, the values **`1`** and **`-1`** in `createIndex()` specify the **sort order of the index**.

* **`1`** → Ascending order (smallest to largest)
* **`-1`** → Descending order (largest to smallest)

## Syntax

```javascript
db.collection.createIndex({ field: 1 })   // Ascending
db.collection.createIndex({ field: -1 })  // Descending
```

---

## Example 1: Ascending Index

```javascript
db.people.createIndex({ age: 1 })
```

MongoDB stores the index like this:

```text
Age
18
22
25
30
35
40
```

Queries such as

```javascript
db.people.find().sort({ age: 1 })
```

can use this index efficiently.

---

## Example 2: Descending Index

```javascript
db.people.createIndex({ age: -1 })
```

Index order becomes

```text
Age
40
35
30
25
22
18
```

This is useful for

```javascript
db.people.find().sort({ age: -1 })
```

---

# Does it matter for single-field indexes?

For **single-field indexes**, **not much**.

If you create

```javascript
db.people.createIndex({ age: 1 })
```

MongoDB can efficiently use it for both:

```javascript
db.people.find().sort({ age: 1 })
```

and

```javascript
db.people.find().sort({ age: -1 })
```

because MongoDB can scan the index **forward or backward**.

So for a single field:

```javascript
{ age: 1 }
```

and

```javascript
{ age: -1 }
```

usually provide the same performance.

---

# When does direction matter?

Direction becomes important for **compound indexes** (indexes on multiple fields).

Suppose:

```javascript
db.people.createIndex({
    age: 1,
    salary: -1
})
```

The index is ordered as:

```text
Age ↑
   Salary ↓
```

This index is perfect for

```javascript
db.people.find().sort({
    age: 1,
    salary: -1
})
```

But it **cannot** efficiently satisfy

```javascript
db.people.find().sort({
    age: 1,
    salary: 1
})
```

because the second field's direction doesn't match.

---

## Another compound example

Index:

```javascript
db.people.createIndex({
    city: 1,
    age: 1
})
```

Efficient for:

```javascript
.sort({ city: 1, age: 1 })
```

and also:

```javascript
.sort({ city: -1, age: -1 })
```

because MongoDB can scan the entire index backward.

Not efficient for:

```javascript
.sort({ city: 1, age: -1 })
```

because the sort directions are mixed.

---

## Summary

| Index              | Meaning                                                                               |
| ------------------ | ------------------------------------------------------------------------------------- |
| `{ age: 1 }`       | Ascending index                                                                       |
| `{ age: -1 }`      | Descending index                                                                      |
| Single-field index | `1` and `-1` are usually equivalent because MongoDB can scan in either direction.     |
| Compound index     | The order (`1` or `-1`) matters for sorting on multiple fields with mixed directions. |

**Interview takeaway:** For **single-field indexes**, the direction (`1` vs. `-1`) rarely matters. For **compound indexes**, the specified direction is important because it determines which sort patterns the index can support efficiently.
