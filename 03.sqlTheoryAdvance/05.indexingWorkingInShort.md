When you create an **index**, the database **does not store the entire row/document** in the index. Instead, it stores:

1. **The indexed column(s) values (the key)**
2. **A pointer/reference to the actual row or document**

Think of it like a book's index.

* **Book index:** Word → Page number
* **Database index:** Column value → Row location



## Example (SQL Database)

Suppose you have a table:

| ID | Name  | Age |
| -- | ----- |  |
| 1  | John  | 25  |
| 2  | Alice | 30  |
| 3  | Bob   | 22  |
| 4  | John  | 40  |

If you create:

```sql
CREATE INDEX idx_name ON users(name);
```

The index (typically a B+ Tree) stores something like:

```
John  > Row 1
John  > Row 4
Alice > Row 2
Bob   > Row 3
```

or more accurately (sorted):

```
Alice -> Pointer(Row2)
Bob   -> Pointer(Row3)
John  -> Pointer(Row1)
John  -> Pointer(Row4)
```

Notice:

* Only the **Name** values are stored.
* Along with **row pointers** (RID/primary key depending on the database).



## In a B+ Tree

Suppose the index is on `Age`.

```
                 [30]
               /      \
        [22,25]      [40]

Leaf Nodes

22 -> Row3
25 -> Row1
30 -> Row2
40 -> Row4
```

Each leaf node stores

```
Indexed Value + Pointer
```

Example

```
25 -> Address(Row1)
30 -> Address(Row2)
```



## What is the Pointer?

It depends on the database.

### MySQL
Secondary indexes store
```
Indexed column
+
Primary Key
```
Example
```
Age = 25
Primary Key = 1
```
Then MySQL uses the primary key to fetch the complete row from the clustered index.


## MongoDB

Suppose a document is

```json
{
   "_id": 1,
   "name": "John",
   "age": 25
}
```

If you create

```javascript
db.users.createIndex({ age: 1 })
```

The index stores something conceptually like

```
22 -> ObjectId(...)
25 -> ObjectId(...)
30 -> ObjectId(...)
```

The pointer is the document's record location (along with `_id` as needed internally), allowing MongoDB to quickly locate the matching document.
