These are SQL **window functions** used to assign rankings to rows. They differ in how they handle **ties (duplicate values)**.

Suppose we have an `employees` table:

| Emp | Salary |
| --- | ------ |
| A   | 10000  |
| B   | 9000   |
| C   | 9000   |
| D   | 8000   |
| E   | 7000   |

Query:

```sql
SELECT
    emp,
    salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
    RANK() OVER (ORDER BY salary DESC) AS rank_num,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank_num
FROM employees;
```

### Output

| Emp | Salary | ROW_NUMBER | RANK | DENSE_RANK |
| --- | ------ | ---------: | ---: | ---------: |
| A   | 10000  |          1 |    1 |          1 |
| B   | 9000   |          2 |    2 |          2 |
| C   | 9000   |          3 |    2 |          2 |
| D   | 8000   |          4 |    4 |          3 |
| E   | 7000   |          5 |    5 |          4 |

---

# 1. ROW_NUMBER()

Assigns a **unique number** to every row.

* No two rows get the same number.
* Even if values are equal, numbering continues sequentially.

Example:

```sql
ROW_NUMBER() OVER (ORDER BY salary DESC)
```

Result:

| Salary | ROW_NUMBER |
| ------ | ---------: |
| 10000  |          1 |
| 9000   |          2 |
| 9000   |          3 |
| 8000   |          4 |
| 7000   |          5 |

**Use cases:**

* Pagination
* Removing duplicates
* Selecting one row from each group

Example: Highest-paid employee in each department

```sql
SELECT *
FROM (
    SELECT *,
           ROW_NUMBER() OVER (
               PARTITION BY department
               ORDER BY salary DESC
           ) AS rn
    FROM employees
) t
WHERE rn = 1;
```

---

# 2. RANK()

Rows with the same value receive the **same rank**.

The next rank **skips numbers**.

Example:

| Salary | RANK |
| ------ | ---: |
| 10000  |    1 |
| 9000   |    2 |
| 9000   |    2 |
| 8000   |    4 |
| 7000   |    5 |

Notice that **rank 3 is skipped**.

**Use cases:**

* Competition rankings
* Leaderboards where ties share the same position

---

# 3. DENSE_RANK()

Rows with the same value receive the **same rank**, but **no ranks are skipped**.

Example:

| Salary | DENSE_RANK |
| ------ | ---------: |
| 10000  |          1 |
| 9000   |          2 |
| 9000   |          2 |
| 8000   |          3 |
| 7000   |          4 |

No gaps appear in the ranking.

**Use cases:**

* Top N distinct values
* Ranking categories without gaps

Example: Top 3 distinct salaries

```sql
SELECT *
FROM (
    SELECT *,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS dr
    FROM employees
) t
WHERE dr <= 3;
```

# PARTITION BY example

Find the highest-paid employee in each department:

| Dept | Emp | Salary |
| ---- | --- | ------ |
| IT   | A   | 10000  |
| IT   | B   | 9000   |
| HR   | C   | 8000   |
| HR   | D   | 8000   |

```sql
SELECT
    department,
    emp,
    salary,
    ROW_NUMBER() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS rn
FROM employees;
```

Output:

| Dept | Emp | Salary | RN |
| ---- | --- | ------ | -: |
| IT   | A   | 10000  |  1 |
| IT   | B   | 9000   |  2 |
| HR   | C   | 8000   |  1 |
| HR   | D   | 8000   |  2 |

Filtering `WHERE rn = 1` returns the highest-paid employee in each department.

# Interview explanation (30 seconds)

* **ROW_NUMBER()** assigns a unique sequential number to each row, even when values are tied.
* **RANK()** gives the same rank to tied rows but leaves gaps in the ranking afterward.
* **DENSE_RANK()** also gives the same rank to tied rows, but it does not leave gaps.
* All three are window functions used with the `OVER()` clause and are commonly used for ranking, pagination, leaderboards, and selecting top N records.
